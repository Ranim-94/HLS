\subsection{Ports on FPGA}

A hardware design exchanges data and control commands with the rest of the system using ports with properly associated interface.

Hardware designs use ports to communicate with other modules on a system.\\ 

Ports have their own hardware structure and can be a simple wire or a complex circuits implementing an interface, realising its sophisticated protocol. Different types of ports are shown  \autoref{fig:input_output:port_example}.

\begin{figure}[h]
\centering
\includegraphics[scale=0.45,frame]{Figures/input_output/port_example}
\caption{Types of Port}
\label{fig:input_output:port_example}
\end{figure}

\begin{itemize}

\item Simple wire

\item 8 bit parallel data bus

\item complex buses such as USB,I2C,$\cdots$


\end{itemize}

For our LED controller project, the \verb|HLS| code is a simple assignment that return a fix value to drive the 8 LEDs.\\

The function argument (that is \verb|*o|) are synthesised into input/output signals in the corresponding hardware design, and we should have some port associated with each of them implmenting some specific interface.\\

In this example, the 8-bit width port implements eight simple wires without any specific protocol (see \autoref{fig:input_output:port_LED_Controller})  

\begin{figure}[h]
\centering
\includegraphics[scale=0.45,frame]{Figures/input_output/port_LED_Controller}
\caption{Port for LED controller}
\label{fig:input_output:port_LED_Controller}
\end{figure}

Now the question is: how can we define this mapping between function arguments and its port interface?

Compiler directive $\leftrightarrow$ \verb|#pragma HLS| will help us in this task.\\

\newpage
Now the compiler directive we use in the LED controller project are used for 2 part:

\begin{figure}[h]
\centering
\includegraphics[scale=0.45,frame]{Figures/input_output/pragma_port_interfaces}
\caption{Compiler directive for port interfaces with function and function arguments}
\label{fig:input_output:pragma_port_interfaces}
\end{figure}

\begin{enumerate}

\item The function argument $\leftrightarrow$ \verb|char *o|

	\begin{itemize}
	\item \verb|#pragma HLS INTERFACE AP_NONE PORT=o| 
	
	\item Since we don’t have any specific interface in this example, the \verb|AP_NONE| is used for this purpose. 
	
	\item In this example, \verb|AP_NONE| interface models a simple wire port in the final hardware design
	\end{itemize}

\item A compiler directive for the \tbi{function itself}

	\begin{itemize}
	\item \verb|#pragma HLS INTERFACE AP_CTRL_NONE PORT=return|
	\end{itemize}

\end{enumerate}

\section{FPGA Structure}

Once the bitstream file is generated, we need to download it to the FPGA baord.

An FPGA is composed form 2 layers: application and configuration layer.\\

An \tbi{application layer}  contains all the \tbi{hardware modules} that can be configured and connected together to implement an \tbi{algorithm or a function}. After configuring this layer, we can apply the input data and get the generated outputs.\\

The \tbi{configuration layer} consists of a set of \tbi{memory cells } used to configure the application layer modules. 
The configuration data saved in this layer is called bitstream and is generated by synthesis tools.

Theoretically, the configuration memories are accessible sequentially, and FPGA bitstream data is written to the FPGA using a streaming scheme.
