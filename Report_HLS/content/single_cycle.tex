\section{Single Cycle Desing Method}

\subsection{Sequential circuit}

\underline{Note:} review also \ref{sec:seq_circuit}, it contains same information in different style.\\

As a reminder, a sequential circuit model consist of a combinational circuit and some memory cells to save the circuit states. The circuit preforms its task through several clock cycles. \\

The clock cycle is defined as longest path in the combinational circuit, which has the highest $t_d$.\\

In each clock cycle, the combinational circuit:

\begin{itemize}

\item read the current state

\item generate outputs and next states

\item save next states in memory cells

\end{itemize}
 
\begin{figure}[h]
\centering
\includegraphics[scale=0.4,frame]{Figures/single_cycle/seq_circuit}
\caption{Sequential circuit}
\label{fig:single_cycle:seq_circuit}
\end{figure}


\newpage
From \verb|HLS| point of view, the \verb|C/C++| function should have 4 part as shown in \autoref{fig:single_cycle:seq_hls}:

\begin{figure}[h]
\centering
\includegraphics[scale=0.4,frame]{Figures/single_cycle/seq_hls}
\caption{Sequential circuit using functions}
\label{fig:single_cycle:seq_hls}
\end{figure}

\begin{itemize}

\item define some register variable using some static variables

\item read the current state

\item perform the task (arithmetic, logical, computing,$\cdots$)

\item update or modify register values

\end{itemize}

The key idea is we want to develop a code that is executed during 1 clock cycle. We call this desing method \tbi{single cycle development}, and later we see that this method gives some nice performances close to \verb|HDL| desing techniques.

\section{General Guidelines}

In this section we present some general guidelines related to \verb|HLS|.


The particular concept is called \textit{IP centric design flow}.

This concept has been seen in sections and project before, and that when we integrate our code into a package called \verb|IP| using tools such as \verb|Vivado|. 

In \autoref{part:fundamentals}, we integrate our \verb|IP| for combinational logic circuit, but now in \autoref{part:sequential}, we deal with sequential circuit and notion related to time (clock period), so we revisit in this chapter the notion of \verb|IP| integration taken into account sequential and time related system.\\

When dealing with  sequential and time related system, the following approach is the following:

\begin{figure}[h]
\centering
\includegraphics[scale=0.4,frame]{Figures/single_cycle/ip_sequential}
\caption{Integration of IP in sequential circuits}
\label{fig:single_cycle:ip_sequential}

\item Divide our application into smaller functions

\item Use single desing approach to describe each function separately

\item Test and synthesis our code, to generate the corresponding \verb|IP|

\item Integrate the \verb|IP| using tools such as \verb|Vivado| to generate the bitstream file and program the FPGA

\end{itemize}

\subsection{Code flow chart}
\label{sub:parallel_ser_flow_chart}

\autoref{fig:single_cycle:parallel_serial_code_flow_chart} shows the code flow chart.

\begin{figure}[h]
\centering
\includegraphics[scale=0.4,frame]{Figures/single_cycle/parallel_serial_code_flow_chart}
\caption{Parallel to serial code flow chart}
\label{fig:single_cycle:parallel_serial_code_flow_chart}
\end{figure}

\underline{Notes:} 

\begin{itemize}

\item the the circuit has \verb|counter| as its state variable

\item \verb|N| denotes the number of bits

\item \verb|d| represents the serial output and \verb|a| represent the input coming from a certain port

\end{itemize}

Now let's start by the flow chart. We begin by the the upper half of it.

\begin{itemize}

\item The desing starts by checking the value of the \verb|begin| signal (see \autoref{fig:single_cycle:parallel_serial_begin_input} for the role of the \verb|begin| signal)

	\begin{itemize}
	\item If it is 1, it resets the \verb|counter| to 0 and then check the \verb|counter| value
	
	\item if it is 0, it directly check the \verb|counter| value
	
	\end{itemize}
\end{itemize}

Now we move the $\mathrm{2}^\mathrm{nd}$ half, based on the value in \verb|counter| variable, we have 4 path in the flow chart:

\begin{enumerate}

\item If the \verb|counter| is 0, then the circuit starts conversion

	\begin{itemize}
	\item It activate the \verb|serial_start| signal
	
	\item Put the LSB at the output line
	
	\item Increment the counter
	\end{itemize}

\newpage

\item  If \verb|counter| $<$ \verb|N - 1| 

	\begin{itemize}
	\item It sends out the next bit
	
	\item increment the counter
	\end{itemize}

\item If \verb|count| reaches \verb|N - 1| bit

	\begin{itemize}
	\item It activates \verb|serial_end| signal, indicating ends of conversion
	
	\item Puts the MSB bit at the output line
	
	\item Insert \verb|N| at the \verb|counter| variable to stop converison in the next iteration
	\end{itemize}

\item If the \verb|counter| is \verb|N|, the circuit does nothing.

\end{enumerate}

Note that the steps of flow chart of \autoref{fig:single_cycle:parallel_serial_code_flow_chart} represents the circuit functionality during a period of clock. In other words, performing 1 iteration of this flow chart represents 1 clock cycle

\subsection{Glitches}
\label{sub:glitches}

Notice that in diagram of \autoref{fig:single_cycle:serial_parallel_hls}, the \verb|end_conversion| variable is generated directly by a combinational circuit.

We should pay attention to such outputs, that is generated by combinational circuit due to \textit{glitches}, which are some undisireable spikes or voltages causing the signal to drift a little.\\

A more details example is shown in \autoref{fig:single_cycle:glitches}.

\begin{figure}[h]
\centering
\includegraphics[scale=0.40,frame]{Figures/single_cycle/glitches}
\caption{Glitches concept}
\label{fig:single_cycle:glitches}
\end{figure}

\begin{itemize}

\item The \verb|and| gate is taken as combinational circuit example

\item In \verb|and| gate, if 1 of the input is low, the output should be low

\item Due to propagation delay in \verb|b|, the input signal may comes after \verb|a|, casusing some glitches

\item To avoid such glitches at the output, we use FF or some register to save the intermediate value, and drive the output signal

\end{itemize}
