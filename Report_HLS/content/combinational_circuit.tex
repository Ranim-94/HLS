\section{Propagation Delay}
\label{sec:prop_delay}

Logic gates doesn't react to input instantly, it takes some time in order correct output is computed. In \autoref{fig:combinational_circuit:delay_gate_example}, an example of NAND gate delay is shown.


\begin{figure}[h]
\centering
\includegraphics[scale=0.40,frame]{Figures/combinational_circuit/delay_gate_example}
\caption{Propagation Delay Example using NAND gate}
\label{fig:combinational_circuit:delay_gate_example}
\end{figure}

\begin{itemize}

\item When state of $a$ changes from 0 $\rightarrow$ 1, the output didn't appear instantly, it appears after some delay $t_p$

	\begin{itemize}
	\item During this period $t_p$, the output of the NAND gate is invalid and it shouldn't take into accounts
	\end{itemize}

\item Same thing when state of $b$ changes from 1 $\rightarrow$ 0

\end{itemize}

\newpage
The concept of delay also apply to combinational circuit, as it shown in \autoref{fig:combinational_circuit:delay_comb_circuit_example}.

\begin{figure}[h]
\centering
\includegraphics[scale=0.27,frame]{Figures/combinational_circuit/delay_comb_circuit_example}
\caption{Propagation Delay Example in a combinational circuit}
\label{fig:combinational_circuit:delay_comb_circuit_example}
\end{figure}

\begin{itemize}

\item A combinaotional circuit consists of many path, and each path has a certain delay

\item The path with maximum delay is called the \tbi{critical path}

\item we have 4 path $P_i$ and 4 operators $g_i$

\item $P_4$ is the critical path since it has the longest propagation delay

\end{itemize}


In \verb|HLS| desing, \tbi{the goal is to minimize this propagation delay as possible}

\item Each $n-1$ adder needs 2 ns cycle for the sum and carry bit to be ready

\item We have $N$ adder so the total delay is equal to $2\, N$ ns
\end{itemize}

\section{Functions in HLS}

Functions (as programming functions we mean) plays an important rule in \verb|HLS|. There are some rules and some coding style we need to adopt in \verb|HLS|, that is different from standard \verb|C|

\begin{itemize}

\item Functions with system calls, that is which call the operating system are not allowed. They are not synthesiable

	\begin{itemize}
	\item Example: \verb|sleep()|, \verb|time()|, \verb|getc()|
	\end{itemize}

\item However, these functions are allowed in \textit{testbench program}

\item \verb|Vitis| ignore functions that have system calls which only display data such as \verb|printf()|

\end{itemize}

\section{Dataflow}
\label{sec:dataflow}

In this part we dive more in describing combinational circuit in \verb|HLS|, and introduce a graphical technique called \tbi{directed acyclic graph} (DAG) to describe such circuits. Let's first introduce some prerequiste concepts.\\

Dataflow graph (DFG) is one of the common modelling techniques for computational systems, which describes movement of data from input to output. \autoref{fig:combinational_circuit:DFG_example} presents an example of DFG for both arithmetic and logical expression.


\begin{figure}[h]
\centering
\includegraphics[scale=0.35,frame]{Figures/combinational_circuit/DFG_example}
\caption{DFG Example}
\label{fig:combinational_circuit:DFG_example}
\end{figure}

\begin{itemize}

\item Operator are represented by the nodes of the graph, and movement of data are represented by arcs of the graph

\end{itemize}


\underline{Graph Types:}\\


A DFG without a loop or cycle is called acyclic DFG (ADFG) or directed acyclic graph (DAG).

Now an ADFG can model a combinational circuit.\\

\newpage
